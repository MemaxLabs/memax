`memax init` connects every agent it finds. `memax connect` connects one,
for an agent you install later or one init skipped. It's safe to run
again: what's already set up stays as it is.

## Usage

```bash
memax connect <agent> [--space <slug>] [--no-hook] [--no-compile] [--agents-md | --gemini-md] [--format json]
memax connect --cloud <agent> [--space <slug>] [--no-hook] [--yes] [--format json]
```

With `--cloud`, it connects the agent's **cloud sandbox** instead of this
machine: Claude Code's cloud sessions or Copilot's cloud agent get a start
key, printed once, and the committed hook file that uses it. See
[Cloud agents](/integrations/cloud-agents).

`<agent>` is one of `claude-code`, `codex`, `cursor`, `gemini`, `copilot`,
`opencode`, `windsurf` or `chatgpt`. Without the CLI installed, run it
with npx: `npx memax-cli connect codex`.

| Flag                  | Description                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `--space <slug>`      | The space. Defaults to this repository's (`.memax.yml`, or its link).                             |
| `--no-hook`           | Don't install the session-start hook.                                                             |
| `--no-compile`        | Don't compile, even in a linked repository.                                                       |
| `--agents-md`         | Gemini CLI only: have it read `AGENTS.md` on this machine, your Personal space's included.        |
| `--gemini-md`         | Gemini CLI only: give the space a `GEMINI.md` that imports `AGENTS.md`. Never with `--agents-md`. |
| `--timeout <seconds>` | How long to wait for the first compile. Default 30.                                               |
| `--cloud`             | A cloud agent (`claude-code`, `copilot`, `codex`): its start key and committed hook.              |
| `--yes`               | With `--cloud`: a connected cloud agent gets a new key without asking.                            |
| `--format <fmt>`      | `text` (default) or `json`.                                                                       |

```text
› memax connect codex

  Memax · connect Codex

  ✓ MCP      settings written; it signs in to Memax on first use
  ✓ Hook     session start, in ~/.codex/hooks.json
  ○          Codex asks you to trust it once: run /hooks in Codex
  ✓ Space    acme-web, at Propose
  ✓ Compile  AGENTS.md, CLAUDE.md written here
```

Run it again and each line says `=`: already set up, nothing changed.

## What it does

1. **MCP settings.** It writes the agent's MCP settings for the remote
   server with OAuth, the way `memax init` does. The agent signs in the
   first time it uses Memax. Settings that already name Memax are left
   alone. For Codex, it offers to run `codex mcp login memax`, which Codex
   needs once.
2. **The session-start hook.** Where the agent has one, it adds
   [`memax hook session-start`](/cli/hook) to the agent's own hook
   settings, so each session starts with what changed since the last. It
   keeps every other hook in the file, and replaces an older Memax entry
   rather than adding a second.
3. **The connection.** An agent connects when it signs in, at **Propose**
   (Cursor and Gemini CLI at **Read**): what it writes waits for you in
   Review. If the agent is already connected elsewhere, `memax connect`
   connects it to this space at that level, or lower if it's lower
   elsewhere. It never raises an agent; you do that in the app.
4. **Gemini CLI and AGENTS.md, when you ask.** Gemini CLI reads
   `GEMINI.md`, not `AGENTS.md`, unless its settings say otherwise. Two
   flags, one at a time:
   - `--agents-md` adds `AGENTS.md` to `context.fileName` in
     `~/.gemini/settings.json` (after `GEMINI.md`, which Gemini's own memory
     keeps writing; your comments and settings stay as they are). Gemini CLI
     then reads every repository's `AGENTS.md` itself, and on a
     [linked machine](/concepts/personal-layer) your Personal space in
     `~/.gemini/AGENTS.md`. This is the one to use.
   - `--gemini-md` gives the space a `GEMINI.md` that imports `AGENTS.md`,
     for teammates who haven't set Gemini CLI up; a `GEMINI.md` you wrote
     stays yours, with one Memax block in it.

   Gemini CLI resolves each file's imports separately, so with both it
   would load `AGENTS.md` twice. `memax connect` refuses the second one and
   says to keep `--agents-md`: stop the space's `GEMINI.md` first. Without
   either flag nothing is added: Antigravity, which replaced Gemini CLI for
   most people, reads `AGENTS.md` as it is.

5. **A first compile.** In a [linked](/cli/link) repository whose files
   aren't compiled and written yet, it compiles once, like
   [`memax compile`](/cli/compile).
6. **Your Personal space, on a linked machine.** Where this machine's home
   is [linked](/concepts/personal-layer), it connects the agent to your
   Personal space too, and adds the agent's own file (Claude Code's rules
   file, a block in Codex's `AGENTS.md`), or moves Codex's block to
   `AGENTS.override.md` once Codex reads that. For OpenCode, which has no
   file of its own, it adds `~/.memax/personal/AGENTS.md` to the
   `instructions` in OpenCode's settings, unless OpenCode reads your
   Personal space from `~/.claude/CLAUDE.md` already. A machine you
   unlinked stays unlinked. Outside a repository, the Personal space is
   the space.

<Callout type="info">
  With the [Memax plugin](/integrations/claude-code-plugin) on in Claude Code,
  the plugin brings the MCP server and the hook, so `memax connect claude-code`
  leaves both to it.
</Callout>

## Agents and their hooks

| Agent       | Hook written to               | Notes                                                     |
| ----------- | ----------------------------- | --------------------------------------------------------- |
| Claude Code | `~/.claude/settings.json`     | Or the plugin.                                            |
| Codex       | `~/.codex/hooks.json`         | Codex asks you to trust a new hook once, with `/hooks`.   |
| Gemini CLI  | `~/.gemini/settings.json`     | Reads `GEMINI.md`: add `--agents-md` to read `AGENTS.md`. |
| Cursor      | `~/.cursor/hooks.json`        | The editor and the Cursor CLI.                            |
| Copilot CLI | `~/.copilot/hooks/memax.json` |                                                           |
| OpenCode    | none                          | No session-start hook; it reads `AGENTS.md` and MCP.      |
| Windsurf    | none                          | No session-start hook that adds context.                  |
| ChatGPT     | none                          | Connects through its connector, in your browser.          |

[`memax hook`](/cli/hook) lists what each agent supports, with links to
its hook documentation. On Windows the hook isn't installed yet: it reads
the daemon's cache, and the daemon doesn't run on Windows.

## Exit codes

| Code | Meaning                                                                     |
| ---- | --------------------------------------------------------------------------- |
| 0    | Connected, or already connected.                                            |
| 1    | A settings file couldn't be written (it says which), or the compile failed. |
| 2    | An agent it doesn't know.                                                   |

Your agents already load the compiled `AGENTS.md` (and `CLAUDE.md`) at
the start of every session. The session-start hook adds what that file
can't say: **what changed since this agent's last session here**.

```text
<memax-context space="acme-web">
Memax: what changed in this repository's compiled context since your last session here. The files themselves are already loaded.
Forgotten by a person (don't use or repeat what these said, and drop any copy you keep):
- M-0131 (2026-10-07)
Waiting for a person to decide (don't decide these yourself; the answer arrives as a kept decision):
- G-0007 "Postgres 17 or 18 for the next migration window?" (asked by codex, open until 2026-10-10)
AGENTS.md is now C-0902 (your last session saw C-0901).
New:
- Never commit generated SDK types by hand; run pnpm gen:v2. [M-0240]
Changed:
- Background jobs run on River, Postgres-backed. We do not use Temporal. [M-0219]
</memax-context>
```

When nothing changed, it prints nothing.

## Install it

[`memax connect <agent>`](/cli/connect) installs it in the agent's own
hook settings. In Claude Code, the [Memax plugin](/integrations/claude-code-plugin)
brings it too. Both run the same command, and only when the CLI is
installed:

```bash
command -v memax >/dev/null 2>&1 && memax hook session-start --agent claude-code || true
```

## Usage

```bash
memax hook session-start [--agent <id>] [--debug]
```

The agent passes its session as JSON on stdin (its id, its directory and
whether it's a new session, a resume or a compaction). `--agent` is
`claude-code` (the default), `codex`, `gemini`, `cursor` or `copilot`,
and sets the output each agent reads, and which compiled files it counts:
`AGENTS.md`, plus the agent's own `CLAUDE.md` or `GEMINI.md` when the
space compiles one. `--debug` says on stderr why
nothing was printed and how long it took.

## What it says

- **Changed lines.** The cited lines that are new or changed since the
  last session, and the memories whose lines are gone. Never the whole
  file: the agent already has it, and a second copy only costs context.
  A line whose cite isn't in the compile Memax made (a hand edit) isn't
  repeated, and neither is a forgotten memory's line.
- **Forgotten memories.** Each memory a person forgot since the last
  session, once, so the agent drops any copy it keeps. An agent's first
  session here hears about the last week's.
- **Decisions waiting.** Each decision an agent asked a person for (a gate,
  `G-`) that still waits, once.
- **Compiles not here yet.** When the space compiled something this
  machine doesn't have yet (the daemon isn't running, or a hand edit waits
  in Review).

The block stays under 3,000 tokens (2,400 for Codex, whose default limit
is about 2,500) and under Claude Code's 10,000-character limit. When it
runs long, the changed lines go first: they're in the file anyway.

## How it stays fast

The hook runs every time a session starts, so it reads only local files
and never touches the network:

- `~/.memax/daemon/warm.json`: what the [daemon](/cli/daemon) knows about
  each linked space (each file's latest compile, recent forgets and
  waiting gates), kept current as the space changes. It holds IDs, never
  memory text.
- The compiled files in the repository.
- What this agent's last session here was told, as hashes.

It exits within 100 ms of starting, Node's own start-up included (on a
4-core machine, a median of about 50 ms against 30 ms for an empty Node
process).

Reading a compiled file at session start counts as reading every memory
in it, which keeps the memories your agents use from fading. The hook
queues that report on disk after it prints; the daemon sends it, or
`memax hook flush` does in the background when no daemon runs.

## Agents with a session-start hook

| Agent                                     | Hook settings (from `memax connect`) | Output                                         |
| ----------------------------------------- | ------------------------------------ | ---------------------------------------------- |
| [Claude Code][claude-hooks]               | `~/.claude/settings.json`            | Plain text, added to the context.              |
| [Codex][codex-hooks]                      | `~/.codex/hooks.json`                | Plain text, added as developer context.        |
| [Gemini CLI][gemini-hooks]                | `~/.gemini/settings.json`            | `hookSpecificOutput.additionalContext` (JSON). |
| [Cursor][cursor-hooks] (editor and CLI)   | `~/.cursor/hooks.json`               | `additional_context` (JSON).                   |
| [Copilot CLI][copilot-hooks]              | `~/.copilot/hooks/memax.json`        | `additionalContext` (JSON).                    |

These have no session-start hook that can add context, so they read the
compiled files and Memax over MCP only:

- **Antigravity CLI** has hooks, but none at session start
  ([docs][antigravity-hooks]).
- **OpenCode** has plugins, not command hooks ([docs][opencode-plugins]).
- **Windsurf** has no session-start event ([docs][windsurf-hooks]).
- **ChatGPT** and **Claude** (chat) read Memax through their connectors.

<Callout type="info">
  Codex asks you to trust a new hook once: run `/hooks` in Codex after
  `memax connect codex`. Cursor and Copilot CLI also run Claude Code's
  hooks; the Claude Code hook stays quiet there, so their own hook speaks.
</Callout>

## Deprecated: `memax hook install|uninstall`

`memax hook install claude-code` installed V1's prompt-reinforcement
hook. Use `memax connect claude-code` instead.

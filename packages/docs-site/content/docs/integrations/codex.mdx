OpenAI Codex supports MCP servers.

## Quick setup

```bash
memax setup --only codex --mcp
```

Setup configures the remote MCP server and walks you through Codex's
one-time OAuth login (`codex mcp login memax`). Unlike most MCP clients,
Codex does not start the OAuth flow on first connect — until the login
runs, `codex mcp list` shows the server as "Not logged in".

## Manual setup

<Steps>
  <Step>
    ### Add Memax to Codex's MCP config

    Codex's config is **TOML**, not JSON, at `~/.codex/config.toml`:

    ```toml
    [mcp_servers.memax]
    command = "npx"
    args = ["-y", "memax-cli", "mcp", "serve", "--agent", "codex"]
    ```

    For remote MCP (hosted), use a `url` block:

    ```toml
    [mcp_servers.memax]
    type = "url"
    url = "https://api.memax.app/mcp"
    ```

    To authenticate with an API key instead of OAuth, add the header
    under a nested `[mcp_servers.memax.http_headers]` table — Codex
    only reads `http_headers`; a plain `headers` table is silently
    ignored:

    ```toml
    [mcp_servers.memax.http_headers]
    Authorization = "Bearer mxk_..."
    ```

  </Step>
  <Step>
    ### Sign in

    For local (stdio) MCP, log in to the CLI:

    ```bash
    memax login
    ```

    For remote MCP with OAuth (no `mxk_` key in the config), authorize
    Codex explicitly:

    ```bash
    codex mcp login memax
    ```

    (Skip both if using remote MCP with an `mxk_` token.)

  </Step>
  <Step>
    ### Verify

    Start a Codex session and ask which tools it has. You should see
    the 9 Memax tools listed in [`memax mcp`](/cli/mcp).

  </Step>
</Steps>

## Usage

Codex can use Memax to:

- Pull project conventions, architecture decisions, and context
  before generating code (`memax_recall`).
- Store decisions and learnings made during a session
  (`memax_push`, `memax_capture`).
- Browse hub / topic structure (`memax_hubs`, `memax_topics`).

## CLI fallback

```bash
CONTEXT=$(memax recall "deployment checklist" --format text)
# Include in your Codex prompt manually.
```
